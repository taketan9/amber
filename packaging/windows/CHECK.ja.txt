第一部 ── 直したものを確かめる
==============================

1. シェルタブが巻き添えで消える（一巡目からの持ち越し）
-------------------------------------------------------

  前回の言葉:
    「シェルパネルに移動、F9で新しいタブ、Shift+F8やShift+F9で分割。
      F9でさらに新しいタブ。その3つ目のタブでF10でクローズ。
      タブの２つめ、分割したものも全部と、タブの3つ目が消えるぞ」

  **決め手はもう一つの方でした** ──「分割した状態でF10を押しても何も
  起こらなかった」。あれが無ければまだ捕まっていません。ありがとう。

  原因: engine は渡されたペア id を持つタブを探し、**見つからないと
  「いま見ているタブ」に落ちて**いました。そこにその id は無いので
  「唯一のペインだった＝タブごと閉じる」と読む。そして「見つからない id」は
  例外ではなく**普通に起きること**でした ── シェルを閉じると同時に kill するので、
  監視スレッドの次の生存確認がそのまま「死んでいる」と答え、engine がもう
  消したペインが自分の死を知らせ、engine がいま見ているタブを消す。

  [ ] `J` でシェル → `F9` で2つ目のタブ
  [ ] `Shift+F8` と `Shift+F9` で分割（2つ目のタブが3ペインに）
  [ ] `F9` で3つ目のタブ
  [ ] 3つ目で `F10` → **3つ目だけ閉じる**
  [ ] 残った2つ目のタブに **分割が3ペインとも残っている**
  [ ] もう一度 `F10`（2つ目のタブで、分割したまま）
      → **確認が出て、押せば2つ目のタブが閉じる**（何も起きない、ではなく）
  [ ] 分割中に `Shift+F10` → **その1ペインだけ**閉じる


2. 「h」の履歴（`o` `O` が履歴を塗り替える？）
----------------------------------------------

  **塗り替えではなく、消していました。** engine の内部でパスを渡されると
  ペインを丸ごと作り直していて、`o` `O` `z` `:cd`・ブックマーク・grep の
  飛び先が毎回、そのペインの**履歴・マーク・並び順・隠しファイル設定**を
  捨てていました。**F5 も同じ扉**を通っていました。

  [ ] いくつかディレクトリを渡り歩いてから `h` → 履歴が並ぶ
  [ ] 左右を違う場所にして `o` → `h` に **さっきまでの履歴が残っている**
  [ ] `,` で並び順を「サイズ」にしてから `z` で別の場所へ
      → **並び順がサイズのまま**（名前に戻らない）
  [ ] 隠しファイルを非表示にしてから `z` で別の場所へ → **非表示のまま**
  [ ] 両ペインが同じ場所で `o`
      → **「両ペインは既に同じディレクトリです」**と出て、何も起きない
        （端末版と同じ言葉です）


3. 「M」のスクロールがマウスに引き戻される
------------------------------------------

  前回「一番下まで下矢印で進んで、さらに下を表示しようとすると
  いったんマウスカーソルのところに戻ってくる」── **扉が2つありました。**
  行の作り直しは前回塞ぎましたが、スクロールそのものも静止したポインタの下の
  行を入れ替えます。座標では区別できません（両方とも同じ座標です）。

  [ ] `M` を開き、**マウスを一覧の上に置いたまま動かさず**、
      ↓ を一番下まで、さらにその先まで押し続ける
      → **一度もマウスの行に戻らない**
  [ ] マウスを**動かせば**その行に移る（殺してはいません）


4. シェルパネルの上辺の線
-------------------------

  平行線が3本ありました ── パネル自身の枠・アクティブタブの**上**辺・
  フォーカス中ペインの全幅の枠。4px 間隔だと「一本の失敗した線」に見えます。

  [ ] シェルを開く → **上辺の線は1本**
  [ ] アクティブなタブは**下**（パネルと接する側）に印がつく
      ※ エディタのファイルタブと同じ形にしました
  [ ] **分割すると**、キーのあるペインに枠が出る（分割していないときは出ない）

A. .md が開かない → シェルにも入力できない
------------------------------------------

  一巡目の言葉:
    「.mdが開かない。別のペインにアクティブを移動して、戻ってくると開いたが、
      もう一回開こうとすると、アクティブペインを変更してもダメだった。
      というか、この状態でシェルペインに移動しても何も入力できないなぁ」

  [ ] **詰まった状態のまま**「:」→ `key` と打ってから `j` を押す
      （`Esc` で止まります）

      ・`Process code=KeyJ` のような行が出る → キーは届いている
      ・**何も出ない** → 鍵盤がどこかに囚われている
      ・**そもそも「:」が効かない** → それも答えです。そう書いてください

      出た行を**そのまま**送ってください。

  あわせて一言:
      詰まる直前に何をしていたか（Ctrl+E？ 比較（=）？ zip の中？）
      その .md は大きい？ mermaid が入っている？


B. 初回だけ IME がオフになる
----------------------------

  cian は触っていません ── IME 連携（`:ime`）は既定でオフで、オンにしない限り
  何も呼びません。**Windows は IME の状態を窓ごとに持つ**ので、新しく作られた窓が
  既定（オフ）で始まる、が素直な説明です。そして窓は**物理キーを読む**ので、
  IME がオンのままでも困らないはず。そこだけ:

  [ ] IME を**オンにしたまま**、一覧で `j` `k` `Space` `/`
      → 効く（IME は切り替わらない）
      → 効かないなら、A と同じく「:」→ `key` で出た行を送ってください

  これが効いているなら、初回オフは実害なしとして閉じます。

1. シェルの表示が変わらなくなる
-------------------------------

  前回の言葉:
    「文字を入力しても　clearと入力しても記載されている文字がかわらない。
      ただ、ぴこぴこしているカーソル位置は変わっているので、
      裏で処理は動いているような気がする」

  **その観察がそのまま答えでした。固まっていたのではなく、
  スクロールバックしたまま戻れなくなっていました。**

  `vt100` はこの二つを別の場所から答えます ── 文字はスクロールバックした側、
  カーソルは生きている側。だから古い文字の上でカーソルだけが動く。
  シェルの上でホイールを回すとスクロールバックしますが、**戻る道が
  ありませんでした**（「打てば下に戻る」というコメントだけが書かれていて、
  実際に呼んでいるものが一つも無かった）。

  [ ] シェルで何か出力（`dir` など）→ **ホイールを上に回す**
      → 表示が過去に戻り、上の帯に「↑ N 行戻っています」と出る
  [ ] その状態で**何か打つ** → **その場で最新に戻って、打った字が出る**
  [ ] `clear` も効く
  [ ] ホイールを下に回しても戻れる（今までどおり）

  IME は自分のキーを一度も見ていません。

  [ ] シェルパネルで **Alt+`** → **IME が切り替わる**
  [ ] **半角/全角キー**でも切り替わる
  [ ] 切り替えたあと、日本語がシェルに打てる
      ※ どちらも Windows に返すようにしたので、cian は何もしません

4. 窓が2つ立ち上がる（run.bat）
-------------------------------

  前回の言葉:
    「cian-guiというCIANのアイコンのウィンドウと、cianというElectronの

  `main.js` が作る窓は**1つだけ**なので、Electron の窓が2つになることは

      セッション中ずっと隣に残る

  [ ] `run.bat` をダブルクリック → **タスクバーのボタンは1つ**
  [ ] 黒いコンソール窓が残らない（一瞬出て消えるのは正常）

  **もし2つのままなら、残った方がどちらか教えてください。**

第六部 ── 五巡目で直した 5 件
=============================

1. System32 がもっさりする ── 645ms → 7ms
------------------------------------------

  **回避策ではなく原因でした。** 一覧は entry 1件につき DOM ノードを1個
  作っていて、描き直しはカーソルが動くたびに走ります。System32 で `j` を
  1回押すたびに 5000 ノードを作って 5000 ノードを捨てていました。

  動いている窓で実測:
        前  5000行 = 1回 645ms（DOM 5000 行）
        後  5000行 = 1回   7ms（DOM   35 行）

  見えている行だけ作り、上下はその分の高さの空き箱で埋めます
  （スクロールバーは本来の長さのまま）。**300件未満は今までと完全に同じ**
  動きです。アイコン表示は除外しています（タイルは折り返すので、
  固定行高の計算は分割線を動かした瞬間に間違うため）。

  [ ] `C:\Windows\System32` を開く → **カーソルの上下が引っかからない**
  [ ] スクロールバーの長さが件数に見合っている（つまみが極端に大きくない）
  [ ] ホイールで一気に下まで、上まで動く。行が抜けない
  [ ] `G` で末尾、`gg` で先頭 → **どちらもカーソルが見えている**
  [ ] `/` で絞り込む → 絞ったあとも普通に動く
  [ ] 普通のディレクトリ（数十件）が今までどおり
  [ ] `:view icons` も今までどおり（ここは変えていません）

  engine はディレクトリを1回読むだけで、遅いのは engine ではありません。
  それでもまだ重ければ、**どの操作が重いか**を教えてください。


2. エディタで「?」がキー一覧を出さない
---------------------------------------

  前回の言葉:
    「テキストエディタで「?」をおうかしてもキー一覧がでない。
      ? (javaScript regexp)って表示されるよ」

  **バーが書かれた時から `? キー一覧` と宣伝していて、何も割り当てられて
  いませんでした。** だから vim が「後方検索」として受け取っていました。

  [ ] `F3` でファイルを開く（vim のノーマルモード）→ `?` → **キー一覧が出る**
  [ ] `Esc` でファイルに戻る
  [ ] 挿入モード（`i`）の途中で `?` を打つと **ただの文字**として入る
  [ ] メモ帳流（`T` → エディタのキー操作）でも `?` はただの文字

  [ ] エディタの下のヒント行に **`Shift+Enter メニュー — 文字コード・blame・

  [ ] `Shift+Enter` → メニュー →「文字コードを指定…」→ Shift_JIS などに変わる

4. カーソル追随プレビューが全画面で出る
---------------------------------------

  設計が違っていました。窓版は全画面のエディタを開いていて、それは
  **glance ではなく open** です。端末版はシェルパネルの画素を借り、
  PTY は裏で走らせたままにします。同じにしました。

  [ ] `:preview` → **シェルパネルの場所**にプレビューが出る（全画面にならない）
  [ ] `j` `k` でカーソルを動かすと**追随する**
  [ ] ディレクトリの上でも中身が出る
  [ ] 画像の上では画像が出る
  [ ] **`Shift+J`（シェルにキーを渡す）→ 本物のシェルが即座に戻る**
      裏で走り続けていたことが分かるはずです
  [ ] ファイルペインに戻ると、またプレビューになる
  [ ] `:preview` をもう一度で止まる
  [ ] シェルを開いていない状態で `:preview` すると、パネルごと開く


5. 「=」の左右比較が何も動かない
--------------------------------

  **動いていました。同じ内容だったのだと思います。** その場合は画面下端に
  一行言うだけでした。端末版は同じ議論を一度通って逆の結論に戻っていて、
  コードにこう書いてあります ──「identical folders only whispered a message
  のせいで、比較が反応しないように感じられた」。

  [ ] 左右で**同じ**ファイルを選んで `=` → **「2つのファイルは同一です」の
      シートが出る**（下端の一行ではなく）
  [ ] 左右で**違う**ファイルを選んで `=` → 並べた差分エディタが開く
  [ ] 左右で同じディレクトリを選んで `=` → 「2つのディレクトリは同一です」
