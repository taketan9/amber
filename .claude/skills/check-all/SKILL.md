# 全部の動作チェック

**単体の検査が通っていても、実物では落ちる。** それが何度もあったので、
ここは三段になっている ── 検査を回す・押して回る・**まだ誰も見ていない
ところを名指しで言う**。

3 つ目がいちばん大事。**「ぜんぶ通りました」は「ぜんぶ見ました」ではない。**
最後に必ず「見ていないところ」を出す（下の一覧をそのまま使う）。

順にやる。前が落ちたら、そこで止めて報せる。

## 一。いつもの検査

```bash
cd ~/workspace/amber
cargo test --workspace
cargo clippy --workspace --all-targets
for t in diagram-test paper-test win-test switch-test contract round-test key-test web-test agree-test words-test paint-test drive-test themes-test; do
  printf '%-14s ' "$t"; node scripts/$t.js 2>&1 | tail -1
done
python3 scripts/requests.py     # 台帳（依頼が守られているか）
python3 scripts/shipped.py      # 未リリースの数
./scripts/mac-build.sh            # mac の予定表に話しかける道具（依頼 462）
./scripts/ios-build.sh && xcodebuild -project ios/Cian.xcodeproj -scheme Cian \
  -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 16 Pro' build \
  2>&1 | grep -E 'error:|\*\* BUILD'
```

**どれが何を守っているか**（重なりと隙間を見るために）:

| 検査 | 見ているもの |
| --- | --- |
| `cargo test` | core の判断（題・前書き・混ぜる・履歴・画像の大きさ・絵文字の表・使われていない画像） |
| `paper-test` | 画面 → テキスト（手で書いた HTML から） |
| `round-test` | **テキスト → 画面 → テキストの往復**（core と切り出しをまたぐ・81 件） |
| `key-test` | 鍵を押してからの往復（Backspace・Tab・Enter・矢印） |
| `switch-test` | ノートを替えたとき、本文が混ざらないこと |
| `diagram-test` | 図の組み立て |
| `win-test` | Windows でだけ出るもの（`file://`・鍵の名前） |
| `web-test` | よそから来た HTML → ノートのテキスト・タイトル・本文らしいところ（24 件）。**iPhone の取り込みもこのひとまとまりを呼ぶ**ので、`clipTitle` と `bestPart` が切り出しの外へ出た日にはここが落ちる |
| `agree-test` | **デスクトップ版と iPhone が、同じノートを同じテキストに戻すか**（橋渡しのコードは別々に書いてある） |
| `paint-test` | **無い色を呼んでいないか** ── 綴りを間違えた `var(--…)` は、何も言わずに透明になる |
| `words-test` | **同じものを、同じ名前で呼んでいるか**（注記の見出しはcore・デスクトップ版・iPhone の三か所にある ── 実際にずれていた） |
| `contract` | crmaine との約束（名前を黙って変えていないか） |
| `drive-test` | **Google のサインインの往復**（偽の Google を手元に立てて）── PKCE の合言葉が付くこと・違う state を受けないこと・切れた鍵が黙って新しくなること・やめると鍵が消えること。本物の Google は人が押すところなので、ここでは押さない |

| `requests.py` | 台帳 ── **人が頼んだことが、まだ守られているか** |

台帳が落ちたら、**直す前にまず訊く** ── そこに書いてあるのは人が頼んだ
ことで、勝手に消してよいものではない。

## 二。デスクトップ版の総ざらい（自動）

```bash
./scripts/walk.sh        # 百六十とおり、押して回る（偽の Drive と同期も含む）
./scripts/walk.sh walk-sync   # 同期の段だけ（一分ほど・同期を直したとき）
./scripts/first-run.sh   # 一本も無いところから始める手順（別に一回）
```

**走っているあいだは、本人のアプリを触らない。** テスト用のアプリは `HOME` を作り替えて出すが、
設定（`amber.json`）だけは本物を読み書きする（macOS の Electron は `appData` に
`HOME` を見ない）── 走査は前後で写しを取って戻すので、**そのあいだに本人が変えた
見方や開いていたノートは巻き戻る**。逆に、本人がそのとき使っていた見方（日・週・
みんなの表）をテスト用のアプリが引き継ぐので、カレンダーの段は `calView`・`calGroup` を段の
頭で決め打つ。`userData` ごと隔離する手は使えない（まっさらな設定のアプリは数分で
固まる ── 鍵束の問い合わせで裏の側が止まる・2026-09-11）。
足場は `ready()` で **`syncAuto` と `nameAuto` を切る** ── 固定のファイル名で押して
回るので、離れるたびに題に合わせて改名されると次の段が迷子になる。改名を見る段
だけ `nameAuto = true` にして、`finally` で戻す（依頼 492）。
足場（アプリと話す口・`step`・記録）は `scripts/walk-harness.mjs` に一つ。
`walk.mjs`（ぜんぶ）と `walk-sync.mjs`（同期だけ）が同じものを使う ── 段を
足すときは、単独でも回せるように別の台本にして `walk.mjs` から呼ぶ。

百とおりほどを実際に押して、3 つを見張る:

1. 例外が飛ばないこと
2. `console.error` が出ないこと
3. **触ったあと、そのノートがまだテキストに戻せること**（`paperToMd`）──
   ここが `null` になったノートは、見た目は何ともないのに保存が黙って止まる

回っているのは: 画面の切り替え・目次・文字の大きさ・列の開け閉め・行き先と
絞り込み・並び順・言葉で探す・タブ・まとめて選ぶ・**記号の帯ぜんぶ（両方の
画面で）**・**キーぜんぶ（表に載っているものを 1 つずつ）**・チェックボックス・絵文字・絵の大きさ・貼り付け・ノートを作る／複製／型から／
題を直す・★・フォルダと色・履歴・パレット・メニュー・**右押し八か所**・
**うまくいかないとき**（存在しないパス・外へ出られない・壊れた HTML・競合の控え）・
**触ったあとの往復**・**混ぜる**（別々の場所は黙って混ざる／**同じ行は両方残って
帯と選び口が出て、「こちらを残す」で片方が消える**）。

### 途中に書く

**入れるものは、端ではなく途中で確かめる。** 端に入るなら途中にも入る
だろう、は成り立たない ── 押した瞬間に焦点がボタンへ移って caret が
先頭へ落ちるからで、それは端に居るときには目に見えない（依頼 461・
絵文字がノートの頭に入った）。`walk.sh` は `途中.md` の長い段落の
まん中に caret を置いて、絵文字と記号を入れる。

### 往復（いちばんの目当て）

**画面を行き来しただけでテキストが変わる**、が実際にあった（段落の改行が空白に、
`*` の点が `-` に、`1. 1.` が `1. 2.` に…）。同期しているフォルダなら、
それが全部むこうへ差分として飛ぶ。

見張りは一つ ── **何もしない往復では、一文字も変わらない。**
一文字打ってから・チェックボックスを押してから・絵文字を入れてから・絵の大きさを
変えてから・貼ってから・記号を付けてから、それぞれ往復する。

**ここは二度、空振りした**（2026-09-09。どちらも変異させて初めて分かった）:

1. 画面を切り替えるだけでは**書き戻しが走らない** ── 何も確かめていなかった。
   人が一文字打った時と同じ合図を、毎周必ず出す。
2. 往復に使うノートが、走査の前半で**既に書き換わっていた** ── 壊れ
   やすい行が残っておらず、鳴りようがなかった。往復専用のノート
   （`往復.md`）を置き、**毎回、元のテキストから始める**。

**検査を足したら、必ず壊して落ちるのを見る。** 落ちないテストは、無いより悪い
（あると思って見なくなる）。

### 触ってはいけないもの

`walk.sh` は自分で守っているが、**手でアプリを起動するときは自分で守る**：

- **本人のノート（`~/Documents/cian`）では絶対に試さない。**
  隔離した `$HOME` を渡す（`HOME=... npx electron ...`）と、ノートは
  そちらの `Documents/` にできる。
- **設定ファイルは、始める前に写しを取り、終わったら戻す。**
  macOS の Electron は `appData` に `$HOME` を見ない ── 隔離した `$HOME`
  を渡しても、`~/Library/Application Support/amber/amber.json` は
  **本物のほうに書かれる**。2026-09-09 に実際に書き込んだ（`open` と
  `tabs` が消えるフォルダを指し、次に開いたとき「開けません」になる
  ところだった）。

アプリは `gui/` から出す（`cd gui && npx electron .`）── repo の根には
`package.json` が無い。エンジンを直したら **`cargo build` してからアプリを
出し直す**（アプリは起動時の実行ファイルを掴んだままなので、`ipcMain` の
新しい口も新しい op も、出し直すまで無い）。

## 二の二。総当たり ── 位置 × 操作のすべての組み合わせ（自動）

```bash
./scripts/walk.sh grid                 # ぜんぶ（二千とおり弱・四十分ほど）
QUICK=1 ./scripts/walk.sh grid         # 主な六行だけ（十分ほど）
ONLY='Backspace|絵文字' ./scripts/walk.sh grid    # 名前で絞る（正規表現）
```

**総ざらいは「一つの操作を一つの場所で」押す。総当たりは「同じ操作を、押しうる
場所ぜんぶで」押す。** 「端に入るなら途中にも入るだろう」は成り立たなかった
（依頼 461 ── 絵文字がノートの頭に入った）ので、場所を軸にした検査を
別に持つ。本人の言葉（2026-09-10）:「ノートの行頭に書く、真ん中の行に
書く、同じ行だけで先頭に記載する、文書の真ん中に記載する、末尾に記載する
── 考えうる限りすべてのオペレーションを各機能について」。

台本は二つに分かれている:

| ファイル | 役目 |
| --- | --- |
| `scripts/grid-page.js` | **アプリの中で動く側。** caret を置く（`spot`）・選ぶ（`select`）・押す（`mark`・`face`・`paste`・`tick`）・いまの姿を返す（`state`）。**何が正しいかは知らない。** 素の JS なので、iPhone の `WKWebView` にそのまま流し込める形 |
| `scripts/grid.mjs` | **判断する側。** 試すノートと狙う行、操作の一覧、決めごと（`expect`）、報せ |

### 軸

- **場所**: 行頭・行中・行末 × かたまりの種類ぜんぶ（見出し・段落・一覧の
  一つめ／途中／入れ子／最後・番号・チェックボックス・済んだチェックボックス・引用の一行目／二行目・
  注記・表のセル／最後のセル・枠の上の段落／下の段落・インデント・末尾の段落）
- **ノートの形**: ふつう・一行だけ・見出しだけ・枠にはさまれた・空・前書きなし
- **操作**: 鍵（Enter・⇧Enter・Backspace・Delete・Tab・⇧Tab・↑↓←→）・
  打つ（あ）・打って戻す（あ→⌘Z）・飾ってから打つ（太字→あ・斜体→あ）・
  帯の記号ぜんぶ・注記（ダイアログに答える）・絵文字（**板を開いてから**）・
  貼る（テキスト・HTML）・チェックボックスを押す
- **選んでから**（丙）: 段落の一部・行をまたぐ・かたまりをまたぐ・見出しを
  含む・セルをまたぐ・表の外から中へ・枠を含む・ぜんぶ × 書式・記号・消す・打つ
- **画面**: 表示・並べて表示（読む側に打つ）・コード画面（記号 × 行の頭／中／末）

### 見張り（決めごとが要らないもの ── 誰が見ても落第）

1. 例外が飛ばない・`console.error` が出ない
2. 触ったあと、まだテキストに戻せる（`paperToMd` が `null` でない）
3. **二度目の書き戻しでテキストが変わらない**（一度保存した形が安定している）
4. **フォーカスが画面から飛ばない**（芯の 1 ──「焦点が飛ぶ」は事故）
5. **入れたものは caret のところに入る**（文字・絵文字・貼り付けたテキスト）── 行のテキストを
   `before.slice(0, pos) + 入れたもの + before.slice(pos)` と突き合わせる
6. **行のどこで押しても同じ結果**（行ごとの記号・Tab・チェックボックス・帯の書式）──
   3 つの位置の結果を突き合わせ、違えば「位置ちがい」で落第
7. 選んで消すとき、**選んでいない文字は一文字も消えない**・表の形が変わらない・
   枠は選んだときだけ消える

### 決めごとのあるもの（`PAPER.ja.md` 六章の乙・丙）

`grid.mjs` の `expect` に写してある ── Tab は一覧の中で一段深く・段落で
インデント・見出しで何もしない、行頭の Backspace は記号を一つ外す、Enter は
見出しの途中で後ろが段落・表のセルで下へ、矢印は枠を跨ぐ、`⇧Enter` は段落の
中の改行、記号は「そのかたまりの次に入る」…。**決めごとを足したら、ここにも
足す。** 六章に無いものは `undefined` を返す（＝見たまま）。

### 落第と「見たまま」は別のもの

報せは `$TMPDIR/amber-grid-out/report.md`（`GRID_OUT=` で変えられる）。
二つに分けて出る:

- **落第** ── 見張りか決めごとに反した。直す
- **見たまま** ── 決めごとが無いところで、何が起きたか。**直さない。本人に
  見せて訊く。** 「正しい挙動がわからなければ勝手に判断せず、僕に聞いてね」
  （2026-09-10・本人）。訊いて決まったら `PAPER.ja.md` 六章に書き、
  `expect` に写す ── 次から失敗として報告される

**見たままを勝手に「たぶん正しい」で流さない。** 一覧のまん中で
Backspace を押したら下の入れ子が消える、のような**テキストが失われる形**は、
決めごとが無くても落第の顔をしている ── そういうものは「見たまま」の中から
拾い上げて、落第と並べて報せる。

### 踏んだ穴（総当たりを作ったときに）

- **狙うテキストは、行の全文にする。** 「下の段落」を狙うと「行末」が `。` の
  手前になり、行末で Enter を押したのに段落が割れた、と報告される（2026-09-10・
  作った日に踏んだ）
- **鍵は CDP の `Input.dispatchKeyEvent` で送る。** `KeyboardEvent` を作って
  投げると、アプリの受け口が受け付けなかった経路（既定の Enter・Backspace・矢印）で
  **何も起きない** ── 「受けなかった」と「既定が壊した」の区別がつかない。
  テキストは `Input.insertText`（IME で確定したときと同じ経路）
- **`paperToMd` は前書きを返さない。** `whole()` と比べるなら `state.head`
  を足す ── 足し忘れて、九十九とおり全部が「二度目で変わる」になった
- **差分は末尾の改行を落としてから取る**（`sameNote` と同じ）── 落とさないと
  差分が末尾までぜんぶ膨らんで、何が変わったのか読めない
- アプリへ渡すテキストは `JSON.stringify` で包んで `${}` に差す（`walk.mjs` の頭と
  同じ理由・逆引用符と円記号の穴）。アプリの中で動く側は別のファイル
  （`grid-page.js`）にしてあるので、あちらは素の JS で書ける
- **ウィンドウが隠れると、Chromium がタイマーを絞る。** 夜通し回した総当たりが七時間
  かかり、「返ってきません」が混ざった ── 数分隠れると一分に一度しか起きない
  （IntensiveWakeUpThrottling）。`walk.sh` は絞りを切る旗を付けてアプリを起動する。
  **長く回すときは `caffeinate -dims` の下で**（端末がスリープすると同じことになる）
- **走っているあいだ、`gui/renderer.js` を触らない。** アプリは起動時に
  読むが、起動は `cargo build` のあと数秒遅れる ── `mutate.sh`（壊して
  戻す）をその隙に走らせると、壊れた版をアプリが読む。総当たりや総ざらいを走らせたら、
  変異テストは終わってから
- **まれに、矢印を送ったのに全角の `１` が混ざる**（2755 とおりに一件・
  2026-09-11・再現せず）。CDP の鍵は OS の入力方式を通るらしく、日本語
  入力が生きていると起きうる。一件だけなら総当たりの側 ── 二度出たらアプリ側を疑う
- **回っているあいだ、画面に出ている amber のウィンドウ（題は「総当たり」）を閉じない・⌘Q しない。**
  閉じると繋ぎが切れて、そこで打ち切りになる（2026-09-11 に三度、本人が
  起きている時間帯にだけ起きた）。本人が端末を使っている時間に回すなら、
  先に一言ことわる。切れたときは「アプリが落ちたのか、繋ぎだけか」を報せに
  記す（`ws.onclose` で `/json` を叩く）
- **止まっても、報せは書く。** 台本が途中で落ちると一時間ぶんの結果が
  全部消える（実際に消えた）── 一件の落ちは失敗として積み、アプリが返って
  こないノートは残りを飛ばし、最後に必ず `report.md` を書く

### まだ総当たりに入っていないもの

- 日本語入力の**変換中**に押す（丁）── CDP の `Input.imeSetComposition` で
  作れるはずだが、まだ書いていない
- 画像を貼る・図（工房）── OS のダイアログと工房を開くので、四の一覧のまま
- コード画面の鍵（Enter・Tab・Backspace は Monaco のもの）── 見ていない

## 三。iPhone

```bash
./scripts/walk-phone.sh    # 二十とおり、まっさらから自動で回る（依頼 448）
```

**デスクトップ版の総ざらいと同じ考え** ── 画素ではなく、画面の下にある関数
（`NotesStore` と `Cian` と `Clipping`）を押す。`--walk` を渡して起こすと
UI の代わりに `ios/Cian/Walk.swift` が走り、落ちた数を持って自分で終わる
（`#if DEBUG` の中なので、配るものには入らない）。毎回**先に消してから
入れる**ので、置き場所を決める経路もサンプルを入れる経路も通る。

**「表示」画面の総当たりも、この中で走る**（`ios/Cian/Mesh.swift`・七百五十六とおり）。
本物の画面（`Paper.page`）を同じ配管で建て、帯の合図（`window.mark`）・絵文字・
キーの受け口を、デスクトップ版の総当たりと同じ場所すべてで押す。仕様の表はデスクトップ版の
`grid.mjs` の写し ── **決めごとを足したら両方直す。** 鍵そのものは送れない
ので、既定の動きは `execCommand`（`insertText`・`delete`・`forwardDelete`・
`insertParagraph`）で起こす。**iOS のソフトウェアキーボードの経路（`keyCode 229` →
`beforeinput`）は、これでは通らない** ── WebKit は消すものが無いとき
`beforeinput` を出さないので、文書の頭の見出しで delete を押したときの

**走査は、アプリの後片づけを肩代わりしない。** 一覧を読み直すのは
`NotesStore` の仕事で、走査が気を利かせて `reload()` を呼ぶと、
**読み直しを忘れた不具合をこちらが隠す**（実際に `remove` から
読み直しを取り除いても「落ちたものはありません」と言った）。

### OS のダイアログが出るので、`walk.sh` では押せない

5. 終わったら**設定を戻し、試し場を消し、ゴミ箱も片づける**。
