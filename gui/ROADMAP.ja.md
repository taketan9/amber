# Electron 版 cian — ロードマップ

`cian-core` の上に、Chromium で描くもう1つのフロントエンドを作る。端末版
（`cian-tui`）は生き続け、`cian-gui`（winit + wgpu）は凍結する。決定の経緯は
記憶メモ `project-gui-electron-decision` にある。

**この計画が存在する理由は見た目ひとつ。** 速度は 2026-08-24 に解けた
（`want_cpu_renderer` の自動判定）。残っていたのは「会社の Windows で文字が
残念」で、原因は cian のどちらの描画経路も **OS の文字描画を使っていない**
ことだった。Chromium は Windows で DirectWrite を使う。

**2026-08-25、実機で判定が出た。** 3つ並べて、Electron 版は `cian.exe`
（「昭和のコンピュータっぽい」）より明らかに読みやすく、日本語も潰れない。
以後の投資はこの1点の実測に立っている。

## 配色

**既定は白磁。** 色は意味のあるところ（ディレクトリ・マーク・カーソル）にだけ置き、
構造は罫と余白で作る。行 26px。**ファイラを毎日は触らない人が読み下せること**を
基準に選んだ ―― 既定文法を notepad にしたのと同じ理屈で、既定は作った人ではなく
初めて開く人のためにある。

**切替は `T` のトグルメニューの中**（端末版と同じキー）。白磁 →
**Solarized Light**（Taketan 本人の一枚。端末版にも同じプリセットがあるので、
**両方を同じ色で使えるのはこれだけ**）→ 陰翳 → 端末譲り。

キーは発明しない。端末版はソートが `,`、隠しファイルは `T` のメニューの中で、
どちらも1文字を割り当ててはいない。**GUI 側で別のキーを当てると、覚える手が
2組になる。**

### キーの突き合わせ（2026-08-29）

`,` と `T` の取り違えは、使っていて気づいたのではなく **端末版のキー表を読んで**
見つかった。同じ読み方で全部を突き合わせたところ、もう1つ出た:

| | 僕が書いていた | 端末版 |
|---|---|---|
| `h` / `l` | 左／右ペインへ | **`h` は履歴**。ペイン移動は `Ctrl+h`/`Ctrl+l` と矢印 |

直したうえで、表にあって GUI に無かったものを足した:
`z`（パス入力移動）・`V`（マーク反転）・`o`/`O`（ペインの位置合わせ）・
`p`（パスをクリップボードへ）・`F5`（読み直し）・`?`（ヘルプ）。

`?` のヘルプは**この表から書き写した**。記憶から書くと、ずれがそのまま
仕様として記録される。

もう一つ出た: `,` は**巡回ではなくピッカー**だった（`n`/`s`/`d`/`e` で直接、
同じキーをもう一度で昇降反転）。巡回にしていたので、`name` から出るのに
2回押す必要があった ── 1回目は反転にしか使われないため。

### ファイルのクリップボード（`Ctrl+C` / `Ctrl+X` / `Ctrl+V`・`y`）

`c`/`m` は反対ペインへ直行する。こちらは**行き先がまだ画面に無い**とき用 ──
ここで掴んで、歩いて、そこで置く。Windows の文字をそのまま使う。

規則は `cian-core/src/clip.rs` に置いて、端末版もそれを使うようにした
（`cian-tui` が自前で持っていたものを移した）。判断が3つあり、どれも
2箇所に書けば必ずずれる:

- 切り取りは貼り付けで消費される。コピーは残る（だから何度も置ける）
- cian 自身のレジスタが OS のクリップボードより優先。空のときだけ OS を見る
- **既にそこにあるファイルの貼り付けは拒否**（無意味か、最悪は自分への上書き）

端末版の既存テスト4件が、移した実装のまま通っている。

### エンジンの通知を誰も聞いていなかった

`preload.js` は骨子を入れた時から `onEvent` を出していたのに、
**レンダラが一度も購読していなかった**。そのため:

- コピーは「0 / 1」と出したまま永遠に止まって見えた
- 終わってもペインが再読込されなかった
- **失敗が一言も出なかった** ── エンジンは正しく拒否していたのに、静かに

道具（下記）で「貼り付けたのに何も入っていない」として出た。

### ファイルを開く（`Enter` / `F3` / `Ctrl+Enter`）

端末版と同じ三分割:

- `Enter` … ディレクトリなら入る、**ファイルならその場で読む**
- `F3` … 同じビューアを開く
- `Ctrl+Enter` … ディレクトリは反対ペインへ、**ファイルは既定のアプリへ**

ビューアは **1画面ぶんの行だけを描く**。端末版がそうなのは端末に選択肢が
ないからだが、ここでは選択で、しかも正しい方 ── 10万行は10万個の要素に
なるし、ビューアで開く価値があるのはまさに長いファイルだ。

**文字コードの判定はエンジンがやる。** ブラウザは UTF-8 しか読まないし、
日本語 Windows で出会うものの半分は Shift_JIS（ログ、バッチ、古い道具の
出力）。生のバイトを渡したら、その判定を JavaScript でもう一度書くことに
なる。開いた時に何だったかは必ずヘッダに出す。

`j k Ctrl+d Ctrl+u gg G / n N q`。検索語は行の中で色を付けるが、
**HTML を組み立てるのではなくテキストノードで置く** ── 中身はファイルなので、
`<script>` を含む行が「動く行」になっては困る。

## シェルの分割

`Shift+F8` 左右、`Shift+F9` 上下、`Shift+F10` そのペインを閉じる、
`Shift+F1`/`F2` で隣へ。`Ctrl+S`（`:sync`）で**全ペインに同時入力** ──
4台のサーバに同じコマンド、が分割の存在理由そのもの。`F12` でパネルを
広げる。

**木にした。リストではなく。** 分割とは1枚を2枚にすることで、その1枚は
以前の分割の片割れかもしれない。「方向1つ + 平らなリスト」は「左右に2枚」を
満たして、**右側をさらに上下に割った瞬間に破れる** ── そして誰もが2番目に
それをやる。

**場所はエンジンが計算する。** 木がこちらにあるので、窓は言われた所に箱を
置くだけ。入れ子の div から同じ算術をもう一度導くのは、2つ目の実装になる。

**大きさは各ペインの箱ぶん**を渡す。パネル全体の幅だと思っているシェルは
違う桁で折り返す ── 分割が壊れて見える古典的な原因。

## マクロ（`@`）

`macro.lua` をそのまま読む。分割ができたので、**`from` と `dir` のとおりに
本物の格子を組む** ── 「タブで代用」は不要になった。`steps` の
`send`/`wait`/`expect` も走る。

`expect` はワーカーで待つ。`sqlplus /nolog` はプロセスが起きた時ではなく
**自分で「準備できた」と言った時**に準備できているので、これがログイン
マクロを可能にしている ── そしてここで待ったらエンジンがログインの間ずっと
止まる。

スクリプトマクロはまだ動かない。そう言って断る。

## 深さを埋める（3）── 文字コード・見えない文字・置換

`:enc` で**開いているファイルを別の文字コードで読み直す**（引数なしで
UTF-8 → Shift_JIS → UTF-16LE → UTF-16BE と回る ── 端末版の使い方は
「文字化けが止まるまで押す」）。

**読み直すのではなく、復号し直す。** バイトはもうエンジンにある。まだ書かれ
続けているログを読み直したら、見ているのと違うファイルが出てくる。

編集用の写しも一緒に付け替える ── でないと保存が「読んだ時の」文字コードで
書き戻して、直したつもりが壊す。

`:ws` は**見えない文字**。行末の空白、意図せぬタブ、そして日本語エディタから
来た全角スペース ── 3つとも黙って壊す種類で、だから「探す」ではなく
「見せるモード」にしてある。全角スペースは Monaco の空白判定に入らないので、
unicode ハイライタを向けている（3つのうち、目で見つけられない唯一のもの）。

`:s/古い/新しい/g` は grep 一括置換と**同じ置換言語**。1ファイルに訊くか
全ファイルに訊くかの違いしかないのに、`s///` の綴りを2つ覚えるのは馬鹿げて
いる。

## 深さを埋める（2）── ビューアの vim 文法

`]]` / `[[`（次・前の見出し）と `za`（折り畳み）。見出しの定義は
`:outline` と同じものを使う ── 1つのエディタに「節」の考えが2つあっては
いけない。メモ帳流でも `Ctrl+]` / `Ctrl+[` で同じ移動ができる。

**`%` は足さなかった。** 一度足して、`moveToMatchedSymbol` という
**元から動いていたもの**を、壊れた自作で置き換えていた。無い機能を足す前に
「もう有るのでは」を確かめる、という話。

### 物差しが目を潰した

監査の JS 検査が `not()` を12件の「呼べない呼び出し」として挙げた。原因は
バッククォートを外す正規表現より前にコメントがあったこと ── 散文に書いた
`` ` `` が数に入って囲みが1つずれ、テンプレートの中身がコードとして数えられる。

**コメントを先に外す版に直したら、今度は黙った。** `'http://…'` の `//` から
行末までが消えて、その行の呼び出しが見えなくなる ── わざと壊しても何も
言わない、いちばん悪い壊れ方。

どちらの順番も間違いなので、**順番を持たないことにした。** いま何の中に
いるかを見ながら1文字ずつ進めば、`//` が文字列の中か外かは迷いようがない。
`${…}` の中はコードなので残す。両方向で確かめてある（誤検知ゼロ、
わざと壊すと1件）。

道具も1つ: 「resource の読み込みに失敗」とだけ言って**どの resource か
言わない**のはブラウザが吐く最も役に立たない真実なので、URL を出すように
した。句読点のキーコードも足した ── `]` に割り当てた機能は、それが無いと
試せない。

## 深さを埋める（1）── 16進編集と blame

**16進編集**（`i` → `0-9 a-f` → `Ctrl+S`）。**上書きのみ**で、ずれない。
バイトを1つ挿入すると後ろの全オフセットが動き、バイナリではそのオフセットが
たいていファイル自身の中に書いてある ── 編集と破壊の差はそこ。

保存は**必ず `.bak` を残す。** ここの変更は読み返して確かめられない唯一の
種類なので、動いていた版が生き残らなければならない。

2桁で1バイトなので、1桁目は**保留として見せる**（書きかけの半バイトは
誰も意図していない）。どのバイトに落ちるかは反転表示で出す ── カーソルの
無い16進エディタは、違うバイトを潰すための道具だ。

**最初の版はバイトを正しく書いて、古い表示のままだった** ── Monaco の
`executeEdits` は読み取り専用だと黙って何もしない。エディタは読み取り専用の
ままでなければならない（でないと桁がテキストとして打ち込まれる）ので、
モデルに直接当てる。

`Ctrl+Shift+B` で **blame**。一覧ではなくガター（左端）に出す ── 訊きたいのは
いつも「*この行*がいつこうなったか」で、同じ行番号を持つ別窓は同じ情報を
腕1本ぶん遠くに置いただけ。

### 資材を削りすぎていた

`min/vs/language`（7MB）を落としたのは、一見あきらかに正しかった:
色は `basic-languages`（81言語で 640KB）が付けるし、バッチファイルに色を
付けるためにコンパイラを配るのは馬鹿げている。

**間違いだった。** Monaco は `.js` を開いた瞬間に
`vs/language/typescript/tsMode` を要求する。ファイルは表示され色も付くので、
被害は**開くたびに例外が1つ**だけ ── 本物の例外を隠すまでは無害な種類。
173MB の zip の中の7MBは、エラーメッセージと引き換えにする額ではない。

（道具も1つ直した: 「resource の読み込みに失敗」とだけ言って**どの
resource か言わない**のは、ブラウザが吐く最も役に立たない真実だ。URL を
出すようにした。）

## キーも突き合わせた

コマンドの次はキー。端末版の表から80個抜いて確かめ、残っていたものを埋めた:
`Shift+H`/`Shift+L`（ペイン間移動）・`F1`〜`F8`（シェルタブへ直接）・
`Ctrl+Shift+矢印`（分割の境界を動かす）・`F12`（パネルの拡大）。

境界の移動は**見えている境界**を動かす ── 葉から外へ歩いて、向きの合う
一番内側の分割。焦点のペインがその分割の前半にいるか後半にいるかで
「広げる」の向きが変わる（右のペインを広げるとは、前半に**少なく**与える
ことだ）。

## コマンドの差はゼロになった

`cian-tui` の `entry(":xxx")` を全部抜いて GUI の表と `comm` する ── 目視では
なく機械で。最初は16個残っていて、いまは**0個**。GUI 側は85個。

（差が無いのは*名前*の話で、中身の深さまで同じという意味ではない。
ビューアの vim 文法や置換の細部は端末版の方が深い。）

最後の6個: `:ai`（自由に訊く）・`:aidiff`（差分を説明）・`:office` /
`:officelink`（クラウド側を開く / `.url` を作る）・`:reload`・`:key`。

**`:key` は押されたキーを飲み込む。** 「効かないキー」を試すためのモードで、
最初に試すのはたいてい和音キーで、その半分は切り取り・削除・上書きだ。
`Ctrl+X` を表示して**同時に切り取る**のは最悪の答え ── 最初の実装がそれで、
道具が捕まえた。

`:reload` は「読み直しました」で終わらせず、**何が変わらないか**を言う。
init.lua の一部は起動時に一度しか読まれないので、黙っていると人はバグを
探しに行く。

`:mark *.rs` は**グロブとして扱う。** 正規表現にすると `.` が何にでも当たって、
**黙って違うファイルにマークが付く。**

埋めたもの（前段）:

`:df`（空き容量）・`:wc`（行/語/バイト）・`:where`（設定がどこにあるか）・
`:mark *.rs` / `:unmark`（ワイルドカード）・`:copyto` / `:moveto`（反対ペイン
以外へ）・`:edit`（`$EDITOR`）・`:stat`・`:theme`・`:redraw`。

`:mark *.rs` は**グロブとして扱う。** 正規表現にすると `.` が何にでも当たって、
**黙って違うファイルにマークが付く。**

`:theme` は名前があれば直接、無ければ一覧を出す ── 「1つしか
ありえない答えを訊くプロンプト」は、人に Enter を押す癖を付けさせるだけ。

## プレビュー（`:preview`）

カーソルを追ってファイルを表示する。**既定で切ってある** ── カーソルが通る
たびに全部読むのは、探している10秒のために払うには高い。入れると
「エラーが入っているのはどれ」を探す最速の道具になる。

カーソルより**一拍遅れて**開く。`j` を押しっぱなしにしたら通過した全部を
開くことになり、意味があるのは止まった1つだけだから。

キーは一覧に残す（`viewer.on` を false のままにしてある）ので `j`/`k` が
動き続ける。だから `Esc` は一覧側から届かせている。

**実測**: Taketan の `macro.lua` の3つが出た。**本番に繋ぐものは走らせて
いない** ── 安全な「Two local shells」でタブ2枚が開くところまで確認した。

## ファイルそのものをクリップボードへ（`Shift+P`）

`p` はパスの文字列、`Shift+P` はファイル。端末版がこれを2つのキーに分けて
いるのには理由があって、**フォルダにパスを貼るのはファイルを貼ることでは
ない。**

3プラットフォームで3つの無関係な仕組み（AppleScript / `wl-copy`・`xclip` の
uri-list / PowerShell の `Set-Clipboard`）。`cian-core` に移した ── 手で
写した三分岐は、いつか1プラットフォームが静かに欠ける。`os_open` がここに
来たのと同じ理由。

実測: `Shift+P` のあと `osascript` で数えて、macOS のクリップボードに
ファイルが1件乗っていることを確認。

## シェルのタブ

`F9` で開き、`F10` で閉じ、`F1`/`F2` で行き来する。タブ1で長いビルドが
走っているのが、タブ2が欲しくなる理由そのもの。

**裏のタブも画面を送ってくる** ── 走り続けるのがタブの意味だから。
名前が付いていなければ、窓は「最後に動いたやつ」を描く: タブ2で流れている
ビルドが、タブ1の上に自分を刷り続けることになる。画面ごとに id を付けて、
表示中でないものは捨てる。

`shellgone` も同じで、**別のタブのシェルが終わったのはパネルを畳む理由に
ならない。**

大きさの変更は**全タブに配る。** 切り替えた時に初めて直すと、切り替えの
1フレームだけ必ず崩れて見える。

## 16進表示と操作キュー

**バイナリを F3 すると「binary に見える」と断られていた** ── 本当だが、
断られた人の手には何も残らない。`view_file` は端末版のビューアが使っている
関数で、テキストも16進も Office も PDF も全部これが答える。そちらに寄せた。

16進は**読むだけ**にしてある。あれはファイルの表示であってファイルではなく、
保存したらダンプを書き戻すことになる。

`:queue` は走っている操作の一覧で、`x` で**1つだけ**止められる。
1万件コピーしているファイラは、どの1万件かを言えるべきだ。

入れる過程で穴が1つ出た: **終わった仕事が一覧から消えていなかった。**
`cancel` しか使っていないうちは無害（誰も読まないフラグを立てるだけ）だが、
キューにすると「これまで走った全部」の一覧になる。`Drop` で外すようにした
── 関数の末尾に書いた削除は、あとで誰かが `return` を足した瞬間に
実行されなくなる。

## タブ

各ペインが一覧を持ち、**表示中のタブが「そのペイン」**。`pane_mut` は今まで
どおり `&mut Pane` を返すので、「このペインに対して何かする」40箇所は
タブという概念を学ばずに済んだ ── 知っているのは切替と開閉の数箇所だけ。

新しいタブは**いま立っている場所**に開く。開く理由はほぼ必ず「ここを残して、
ちょっと別の所へ行きたい」だからだ。

`t`/`F9` 新規、`w`/`F10` 閉じる、`F1`/`F2` 前後、`Shift+Tab` 次へ。
タブが1つのときは**列を描かない** ── 1つしか無いタブ列は、何も言っていない
1行のクロームだ。

**応答の作り方を1箇所に揃えた。** 素のペインを返す形はタブが無いうちは動くが、
入れた途端に「操作のたびに列が消える」になる ── ファイル名を変えたら
タブバーが消えるのは、タブバーが無いより悪い。

そのほか端末版と同じ綴りで: `:mkdir -p`・`:touch`・`:cp`/`:mv`/`:rm`・
`:pwd`・`:ls -a`・`:q`。`:mkdir -p` の取り消しは**一番外側**を覚える
（内側を覚えたら残りが取り残される）。

## AI とショートカット

設定の住所が決まったので、両方が開いた。

**AI** は `:aicmd`（説明からコマンド）と `:ailog`（ログの診断）。
プロンプトは**端末版のものを一字一句そのまま**エンジンに置いた ── 同じ問いに
2つの前端が別々に訊いたら、別々の答えが返り、それは誰にも追えない違いになる。

`:aicmd` の答えは**シェルのプロンプトに置くだけで、実行しない。** 外した
モデルは外したモデルで、Enter を押すのは人であってプログラムではない。

**ワーカーで走らせる。** 最初は同期で呼んで、python の子プロセスが他人の
ネットワークの向こうを待つあいだ**エンジン全体が止まった** ── 一覧の1打鍵が
ログの質問の後ろに並ぶ。フリーズにしか見えない。

**ショートカット** は `s`。端末版の `shortcuts.lua` をそのまま読み書きする。
`:bookmark` で今の場所を登録。実測: **端末版で登録済みの `work/tmp` が
そのまま GUI に出た。**

## 設定はどこに住むか ── 決着

**何か月も開いていた問い**で、答えが高くつくように見えていた: `init.lua` を
読むには Lua が要り、Lua には C コンパイラが要る。

調べたら、**端末版が既に `mlua`（vendored）を積んでいて、Windows のリリース
は毎回それをコンパイルして緑だった。** 守ろうとしていた性質は、とっくに
手放されていた。しかも同じことが SFTP でも起きていた ── **確かめずに置いた
懸念が2つ、機能をひとかたまりずつ塞いでいた。**

置き場所は**端末版の状態ファイルそのもの**（`state.toml`、`key = value`）。
`theme` や `font_level` の隣に `gui_look` と `gui_editor` が並ぶ。
一方で選んだ配色は、もう一方が開くときの配色になる ── そうでなければ
1つの名前を着た2つのプログラムだ。

**`init.lua` は触らない。** あれは手で書かれ、コードとして読まれるファイルで、
書き換えるプログラムは人のコメントを整形し直すことになる。

`state_get`/`state_set` は `cian-lua` に移した（設定パスを持っている所）。
端末版のテスト3件は移したまま通っている。

## M5 サーバ（SFTP）

**調べた結果、代償はゼロだった。** `cian-scp` は `russh`（純 Rust）で、
**端末版が既に積んでいて Windows のリリースは今日も緑**。数GBのコンパイラが
問題になるのは*実機でビルドする*場合で、実機は exe を受け取る。
半年前の懸念は、確かめずに置いたまま機能ひとかたまりを塞いでいた。

転送ダイアログは作らない。**行は行**で、`Enter` でディレクトリへ入り、
`..` で上がり、`c` で反対ペインへ ── それがアップロードかダウンロードかは
**立っている側が決める**。プログラムが既に知っていることを人に訊かない。

サーバを表示しているペインは**枠の色が変わる**。行はローカルと見分けが
つかないので、他人のサーバを自分のディスクと間違えるのは、色を1つ使う
価値のある唯一の取り違えだ。

パスワードは**訊くだけで、どこにも書かない**。cian に「持たないより
ましな持ち方」は無い。伏せ字で入力し、接続まで持って捨てる。

**未検証**: 成功した接続はまだ通していない（手元にサーバが無い）。
組み立てと失敗経路は実測済みで、下回りは端末版と同じ `cian-scp`。

## M4 シェル ✅

**端末はエンジンに置いた。** Electron の定番は `node-pty` ── ネイティブ
モジュールで、C++ ツールチェインと Electron の ABI に対する再ビルドが要る。
SFTP のときに断った数GBと同じ話だ。

`cian-pty` は `portable-pty` と `vt100` で、**どちらも純 Rust**。しかも
端末版がシェルを読んでいるのと同じエミュレータ。だから:

- 窓側はエスケープシーケンスを1つも知らない。**グリッドを渡されて描くだけ**
- エミュレータは1つ。20年ぶんの端末の癖に**2つ目の答えを持たない**
- 動かす機械にコンパイラが要らない

`Shift+J` で開き、`Esc` でファイルへ戻る（`Esc` 2回でシェル自身に渡る ──
vi がそこに住んでいるので）。`Shift+PgUp/PgDn` で遡る。
`:!コマンド`（`%` 選択・`%f` ファイル・`%d` ディレクトリ）と `:each`（`{}` がパス）。

色は**名前のまま送る**。16色を hex に焼くと、シェルだけが白磁も陰翳も
無視することになる。256色と真色だけは、プログラムが意図して選んだ値なので
固定する。

### ロケールが無い

打った日本語だけが `<0083><0086>` と化けた ── **コマンドの出力は正しい**のに。
zsh が「印字できないバイト」を表す書き方で、原因は `LANG` が無いこと。

**端末には必ずあるので、端末版はこれを考える必要が一度も無かった。**
Finder やエクスプローラから起動した窓には無い ── つまり実機がまさにそれだ。
`cian-pty` は `TERM` は立てていたのにロケールは立てていなかったので、
**無いときだけ** UTF-8 を立てるようにした（Windows はコードページなので除く）。

これは端末版にも効く修正で、フォントの問題に見えて違う種類のバグだった。

### Electron の既定メニューが Windows でキーを7つ食う

より先にキーを取るので、全マークもファイルクリップボードも redo も、
**Windows だけで死ぬ。**

**Mac からは見えない。** 同じメニューが Cmd に載っているからで、こちらで
いくら押しても何も起きない。`Ctrl+R` が redo にならないのを追ってメニューに

いまは決めてある: Windows / Linux はメニューなし（全画面のキーボード
プログラムに、バーの1行は要らない）。macOS は appMenu / editMenu /

Cmd+C / Cmd+V が効かなくなる**ので、これは選択ではなく制約。

**実機で確かめるまで直ったとは言わない。**

### 要求は左右**両方**のカーソルを述べる

`=` は1つのキーで、答えは**2つのカーソルが指しているもの**で決まる。
ところが要求は片方しか述べていなかったので、ディレクトリ比較が「L と L」
を比べて0件を返していた ── 正しい答えだが、訊きたかった問いではない。

### 土台: 結果を出す1枚の画面

検索、容量分析、チェックサム、履歴 ── **問いごとに画面を作らない。**
違うのは Enter が何をするかだけなので、画面は `pick` を受け取り、あとは

## M3 エディタ ✅

**読むのも書くのも Monaco 一本。** 端末版に別のエディタが無いのと同じで
（あちらはビューアがその場で編集可能になる）、手書きのビューアと本物の
エディタを並べたら、移動と検索の実装が2つになる。それが必ずずれるのは、
今週ずっと潰してきた形そのものだ。1時間前に自分で書いたビューアを消した。

- **既定はメモ帳流**、`T` のトグルメニューで **vim** に切替（Taketan 用）
- vim はノーマルモードで開く。`i` 挿入、`:w` 保存、`:q` 閉じる、`:wq` 両方
- `Ctrl+S`（mac は Cmd+S）で保存。**元の文字コード・改行・BOM のまま**
- 閉じるのは **同じキーを3回連続**（端末版と同じ）。メモ帳流は `Esc`、
  vim 流儀は `Esc` か `Backspace`（挿入中は数えない）。`F3` は1回で閉じる

3回にする理由は端末版の言い分そのままで、こちらでも実際に困った:
**1回で閉じると、Esc は反射で押される唯一のキーなのに、未保存を捨てる
キーになる。** かといって「未保存なら確認」だけにすると、Esc が確認を
出し、Esc が確認を消し、また Esc が確認を出す ── 保存する以外に出口が
無くなる。Taketan の実機でそうなった。間に別のキーが入れば数え直す
（Esc・Backspace・Esc は3回の打鍵で、意図ではない）。数は表示しない。

保存はエンジンが**読んだ時の `TextFile` を通して**書き戻す。前端が言う
パスや文字コードは使わない ── 取り違えたら、1行の編集が全行の差分になり、
Shift_JIS のログなら書いた道具が二度と読めないファイルになる。
実測: Shift_JIS + CRLF のファイルを開いて1行足して保存し、バイト列が
`8d 73 96 da`（Shift_JIS の「行目」）と `0d 0a` のままであることを確認。

### 重なりの順番

オーバーレイ3つのどれにも `z-index` が無く、**このファイルに書いた順**で
重なっていた。エディタを最後に足したので、**エディタが自分の出す質問を
覆っていた** ── 未保存のファイルを閉じようとすると、確認は開いているのに
裏で、画面上は何も起きない。Taketan の実機で「Ctrl+S しないと閉じられない」
として出た。

いまは書いてある: `#view` 10（一覧を置き換える面）→ `#find` 20 → `#ask` 30
（常に最前面、答えるものだから）。4つ目を足すのが事故ではなく判断になる。

### vim のコマンドラインの場所

monaco-vim は `--NORMAL--` を左に残したまま `:` を出す。vim はそうしない
── 最下行が**コマンドラインになる**。残したせいで `:` が左端から 108px の
ところに出ていて、そんな場所にコマンドラインを置く vim は無い。
出ている間はモード表示を隠し、入力が行いっぱいを取るようにした（18px、
`:` 1文字ぶん）。

### 確認ダイアログの焦点が嘘をついていた

焦点は「やめる」に置いていた ── キーボードに肘をついても消えないように、
という意図で。だが **Enter は焦点がどこにあろうと「はい」を返す**ので、
何も守っていなかった。やっていたのは、`(Enter)` と書いたボタンが実行する
一方で `やめる` に輪を描くことだけで、起きることの逆に読める。
焦点は Enter が行く先へ移した。守っているのは「訊かれること」そのものだ。

### 入力中は枠の色が変わる

端末版は、`:` も `/` もビューアも、**入力中のプロンプトに1つの見た目**を
与えている（濃いバーに白抜き・太字）── 「いま文字を取っている」を考えて
判断させないため。こちらではエディタの枠そのものをアクセント色にした。

### 資材（`gui/vendor/`）

`node gui/vendor.js` が node_modules から実行時に要るものだけを取り出す。
コミットはしない ── 同梱フォントと同じ理由で、数MBが全クローンに永久に
残るのは割に合わない。オフライン用の source バンドルには入れる。

**13MB → 5.3MB。** `min/vs/language` の 6.9MB は言語*サービス*（TypeScript
コンパイラ一式、CSS/HTML/JSON の解析器）で、IDE の赤波線のためのもの。
バッチファイルに色を付けるためにコンパイラを配るのは馬鹿げている。
色は `basic-languages`（81言語で 640KB）から来る。

### 直したもの3つ（どれも道具が出した）

1. **worker のパスが絶対でなかった** ── worker はページのディレクトリを
   知らないので、相対パスは `file:///vendor/...`（ディスクの根）を探しに行く。
   エディタは例外を出し、後ろに空の窓が残った。
2. **ビューアのリスナが capture 段階で全キーを止めていた。** 他のオーバー
   レイはそれで正しい（画面全体がそれだから）が、ここでは致命的で、
   Monaco のキーバインドが1つも発火しない。文字入力は別経路なので通り、
   **保存しようとするまで完全に生きて見えた。**
3. **開いた瞬間に「未保存」になっていた** ── エディタに中身を入れるのも
   変更のうちだから。今は Monaco の alternative version id と比べている。
   おまけに、編集を undo で元に戻したら未保存が消える（フラグでは消えない）。

### カーソルの持ち主を決めた

カーソルは窓の中で動く。`j` のたびに1行だけ塗り直すのに往復していたら
話にならないからだ。ところが**エンジン側のカーソルは `enter` と `mark` でしか
更新されていなかった** ── `j` を3回押して `r` を押すと、3行上のファイルの
名前が変わる。

ペインを名指しする要求は、カーソルも一緒に述べる。受け取るのは
`take_cursor` の1箇所だけ（各ハンドラではなく）で、送るのは `ask()` の
1箇所だけ（十数箇所の呼び出し側ではなく）。

### キーを実際に押す（`gui/drive.js`）

```
node gui/drive.js              # 決まった一巡
node gui/drive.js , d T Esc    # 好きなキー
```

Electron を CDP のポート付きで起動し、`Input.dispatchKeyEvent` で本物の窓に
キーを送って、ステータス行と開いているシートを読み返す。依存は足していない
（Node 22 以降に WebSocket が入っている。オフラインでビルドできることが
売りのプロジェクトに、この程度で依存を増やすのは割に合わない）。

道具自身も2度直っている。**砂場を自分で作る**ようになったのは、round が
コピー・移動・削除を押すからで、ホームに向けたらそこで3つとも起きる。
**ポートを実行ごとに変える**ようになったのは、前の実行の窓が固定ポートに
居座っていて、キーが死んだ砂場に届き、報告が別人のファイルの話になって
いたから ── 繋いだ先が自分の砂場かを毎回確かめる。

**これが無かったので、エンジン側だけが検証されていた。** 壊れたのは常に
レンダラ側で、そちらはキーを押すまで壊れない。実際、`call is not defined` と
`refresh()` の二重定義は `node --check` も `cargo test` も `audit.py` も
通り抜けて、Taketan の画面で落ちた。道具を入れた直後に、さらに例外が3件と
`o` の「undefined へ」（`path` ではなく `cwd` だった）が出ている。

**どこに保存するかは未決。** [[project-gui-electron-decision]] で設定は `init.lua`
一本と決めたが、`cian-server` から Lua を読むには `cian-lua` が要り、それは
`mlua` → `lua-src` → `cc` を引く ―― **C コンパイラが必要になり、「350MB の Rust
1本で足りる」が壊れる**。実測: cian-lua は100クレート、`cc` と `lua-src` 込み。

急がない。いまの運用（exe を運ぶ）では CI 側に C があるので今日は困らないが、
**SFTP の判断と同じ天秤に載る**ので、まとめて決めるのがよい。

## M1 — ファイラと名乗れるところまで

**ここを越えるまでは「一覧が出るだけのもの」。** マークして、コピーして、
消せて初めてファイラになる。

- マーク（Space / Ctrl+A / 範囲）
- コピー・移動・削除・リネーム・新規作成。**すべて確認を出す**
- 進捗と中止。長い処理はキューに並ぶ
- Undo（直前のリネーム・作成・移動）

**この段でプロトコルの形が変わる。** ここまでは「訊いて答える」だけだったが、
進捗は**サーバから押し出す**必要がある。`id` の無い通知を足す。**後から足すと
全部書き直しになるので、ここで決める。**

**危険なところ**: 確認ダイアログの作法。端末版は「うっかりで失うものはない」を
設計の芯にしている（[[project-copy-move-design]]）。ここを軽く作ると、cian で
なくなる。

## M2 — 見つける ✅ 済（サーバ側は検証済み、キー割当は未検証）

- フィルタ（`/`）、インクリメンタル検索
- ファジーファインダ（`//`）、ジャンプ（`Z`）、コマンドパレット
- ソート、隠しファイル表示

**M1 の押し出しがそのまま効いた。** ツリー走査は端末版で一度失敗している
（メインループを止めていた）ので、最初からワーカーにした。

**歩き方は幅優先。** 深さ優先だと5万件の上限が `target/` で埋まり、
「renderer」で `gui/renderer.js` ではなくビルド成果物が返ってきた ―― ランキング
は最初から正しく、**ファイルがまだ見られていなかっただけ**。外側から輪を広げれば、
無視するディレクトリの一覧（プロジェクトごとに当て推量になる）を持たずに済む。

**ランキングは Rust 側に一本化。** ファジー照合は小さな判断の集まりで、実装が
2つあると1週間でずれる。パイプ越しの往復は照合そのものより安い。

## M3 — 読む・書く

- ビューア（テキスト・画像・16進・書庫・Office/PDF）
- エディタ = **Monaco ＋ monaco-vim**。自前で vim を書かない
- cian の文法を `unmap` / `defineEx` / `defineMotion` で被せる

**決定済み**: `Ctrl+A` は全選択（数値インクリメントを捨てる）。Windows の
ショートカット7つは残す。**7つで止める** — 8つ目は同じだけ議論する。

**持ち込みの形が変わる段**でもある。Monaco はレジストリから来るので、
`node_modules` をオフラインでどう運ぶかをここで決める（CI に Windows 用を
作らせるのが筋）。

## 決めていないこと

**端末版の全部を持っていくのか。** GUI の相手は「メンバー」で、端末版の相手は
Taketan 自身。この非対称は既定文法（notepad / vim）で一度採用している。同じ
理屈が効くかもしれないもの:

- **マクロ**（`@` / `q`）— 玄人向け
- **SSH / リモートペイン**（SFTP）— 玄人向け、かつ `cian-server` に SFTP を
  持ち込むと C のビルドが復活し、**社内で Rust を触るときの敷居が数GB上がる**
- **AI** — 端末版にあるものをそのまま持っていくか
- **git / svn** — 使う人がいるかで決まる

**急がなくてよい。** ただし M4 までにどこかで決めないと、`cian-server` の
依存が膨らんでオフライン持ち込みの前提が変わる。
