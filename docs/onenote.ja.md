# OneNote を、1時間ごとに ambər へ写す

OneNote のノートブック / セクショングループ / セクション / ページを、**その形の
まま**フォルダと `.md` にして書き出す。往きだけ ── ambər で直したものは
OneNote へは戻らない。

道具は `scripts/onenote2md.py`。設定するのは「1時間ごとに、更新があったノート
だけ」の部分で、それはタスク スケジューラの仕事になる。

## できること・できないこと

**できる**

| | |
|---|---|
| 階層 | ノートブック › セクショングループ › セクション がそのままフォルダ。サブページは親ページ名のフォルダへ |
| 中身 | 見出し・太字/斜体/取り消し線・箇条書き・番号・引用・コード・表・リンク・**画像** |
| 表 | OneNote 側で「見出しの行」にしてある行だけを見出しにする。無ければ空の見出しを置く ── 1 行目を見出しに使うと、**そのデータが一行、表から消える** |
| チェックボックス | OneNote の「タスク」タグ → `- [ ]` / `- [x]`。ほかのタグは行頭に `` `#名前` `` |
| 差分 | **変わっていないページは書かない**（前書きの `modified` と OneNote の `lastModifiedTime` を突き合わせる） |
| 前書き | `title` / `created` / `modified` / `onenote_id` / `onenote_path` ── ambər はこの `title` を題として読む |

**できない**

- **手書き（インク）**。`> [インク: 変換対象外]` と置くだけ。OneNote の XML に
  文字は入っていないので、こちらでは何もできない。
- **表の升の中の改行**。Markdown の表に改行を入れる書き方が無いので、空白で
  繋ぐ。（`<br>` では ambər の画面に `<br>` という字が出る ── 本文の札は
  ぜんぶ字にして出す決めごとなので。）
- **行頭の記号を逃がすこと**。OneNote で `# 会議` と書いた段落は、写した先で
  見出しになる（`- ` や `1. ` も同じ）。ambər はバックスラッシュの逃がしを
  読まないので、逃がすと今度は `\#` の `\` が字として出る。**直すなら
  ambər の側**（iPhone は逃がしを読むので、いま窓と食い違っている）。
- **添付ファイルの中身**。`添付ファイル: 見積.xlsx` と名前だけ残す。
- **ページ上の自由な配置**。OneNote は箱をどこにでも置けるが Markdown は一列なので、
  **上から下・左から右**の順に潰す。
- **パスワードをかけたセクション**。鍵が開いていない限り飛ばす（そして
  `--prune` もその下には触らない ── 下記）。
- **往復**。ambər 側で直したページは、次に OneNote 側が更新された時点で
  上書きされる。`--prune` を付けているなら、OneNote で消したページに対応する
  ものは消える。**片道だと思って使う。**

## 要るもの

- **Windows**。デスクトップ版 OneNote（Microsoft 365 / 2016 以降）。
  ストア版の「OneNote for Windows 10」は COM を持たないので**使えない**。

> **二つとも入っていることがある。** 会社の端末でそうなっていた
> （OneNote 365 と OneNote for Windows 10）。入っていること自体は害では
> ないが、**ふだんストア版で書いていると、デスクトップ版には一冊も開いて
> いない** ── そうなると繋がっても写すものが無く、「繋がったのに何も
> 出ない」になる。**写すノートブックは、デスクトップ版のほうで開く。**
> どちらが入っているかは `--check` が言う。
- Python 3 と `pip install pywin32`。
- 写したいノートブックが OneNote 上で**開いている**こと。閉じているものは
  OneNote から見えないので、写しも作られない。

> Excel VBA でも同じことはできる（`CreateObject("OneNote.Application")` で
> 同じ COM に繋がる）。ここに置いてあるのが Python というだけで、
> 仕組みは同じもの。

## まず一回、手で

何が出るかを見てから決める。書き込みなしで階層だけ:

```bat
py -3 scripts\onenote2md.py --out "%USERPROFILE%\Documents\amber\OneNote" --dry-run
```

よさそうなら一回ぶん:

```bat
py -3 scripts\onenote2md.py --out "%USERPROFILE%\Documents\amber\OneNote" --sync
```

**最初の一回は全ページを書くので長い。** ページ数と画像の量によっては数十分。
二回目からは変わったページだけになる。

セクショングループが深いノートブックは `--flatten-groups` で
「グループ › セクション」の一段に畳める（ambər の一覧はフォルダ 8 段まで）。

## 写すものを選ぶ

全部でなくていいなら、三通り。

まず**何があるか**を見る。書き込みはしない:

```bat
py -3 scripts\onenote2md.py --out ... --list
```

```
  仕事/議事録            412 ページ
  仕事/案件/A社           12 ページ
  仕事/案件/B社            8 ページ
  仕事/秘密                0 ページ  （鍵）
  私用/買い物              3 ページ
```

この道をそのまま `--only` に書く。

| | |
|---|---|
| `--notebook 案件` | **ノートブック**で絞る（名前に部分一致・複数可） |
| `--only 仕事/議事録` | **セクション**で絞る。上の道に部分一致・複数可 |
| `--skip 仕事/私的` | これだけ外す。**`--only` より強い** |

`--only 仕事` のようにノートブック名だけ書けば、その下ぜんぶ。
`--only 案件/A社` のようにグループから書けば、そのセクションだけ。大文字小文字は
問わない。`--only` を重ねれば足し合わせ:

```bat
py -3 scripts\onenote2md.py --out ... --only "仕事/議事録" --only "私用/買い物" --sync
```

絞りが狙ったものを拾っているかは、書き出す前に見られる ── **`--list` に同じ
`--only` / `--skip` を付ける**と、外れるものに `×` が付く:

```bat
py -3 scripts\onenote2md.py --out ... --list --only "仕事/議事録"
```

```
  仕事/議事録            412 ページ
× 仕事/案件/A社           12 ページ
× 私用/買い物              3 ページ
```

**当たるのは OneNote 側の道で、出力の名前ではない。** `--flatten-groups` を
付けると出力は `仕事/案件 › A社/` になるが、`--only` に書くのはいつも
`案件/A社`。旗の有無で同じ `--only` が違うものを拾ったら、絞りとして使えない。

**ページ単位では選べない。** セクションまで。要るなら言ってほしい ── 道の当て方が
変わる（セクションを開く前に「この下にページが当たるかもしれない」を判断する
必要が出て、部分一致では足りなくなる）。

## 1時間ごとにする

`scripts\onenote-hourly.cmd` の冒頭 2 行（出力先と記録の置き場所）を自分の
ものに書き換えてから、タスク スケジューラに登録する。

### タスク スケジューラの画面から

「タスクの作成」（「基本タスクの作成」ではなく）。

- **全般** ── 「**ユーザーがログオンしているときのみ実行する**」。
  ここが肝心で、「ログオンしているかどうかにかかわらず実行する」にすると
  **動かない** ── そちらはデスクトップのないセッションで走り、OneNote の COM は
  そこでは掴めない。
- **トリガー** ── 「毎日」→ 詳細設定で「繰り返し間隔: 1 時間」「継続時間: 無期限」。
- **操作** ── プログラムは `pythonw.exe`（`python.exe` **ではない** ──
  そちらだと一時間ごとに黒い窓が開く）。引数は一行で:

  ```
  "C:\...\amber\scripts\onenote2md.py" --out "C:\Users\<あなた>\Documents\amber\OneNote" --sync --prune --log "C:\Users\<あなた>\AppData\Local\onenote2md.log"
  ```

  写すものを絞るなら、ここに `--only "仕事/議事録"` を足す（`--list` で確かめた
  道をそのまま）。**絞ったまま `--prune` を付けても、外したセクションの写しは
  消えない** ── 下記。

- **設定** ── 「タスクが既に実行中の場合: **新しいインスタンスを開始しない**」。
  （スクリプト自身も鎖を持っているので二重の守りになる。最初の一回が一時間を
  超えたときに効く。）

### コマンドからなら

```bat
schtasks /Create /TN "amber\OneNote の写し" /SC HOURLY /IT /F ^
  /TR "\"C:\Program Files\Python312\pythonw.exe\" \"C:\...\amber\scripts\onenote2md.py\" --out \"%USERPROFILE%\Documents\amber\OneNote\" --sync --prune --log \"%LOCALAPPDATA%\onenote2md.log\""
```

`/IT` が「ログオンしているときのみ」。パスの `\"` は必要 ── 道に空白が入る。

### 動いているかを見る

```bat
type "%LOCALAPPDATA%\onenote2md.log"
```

一回ぶんの終わりに、こう出る:

```
完了: ページ 412（書いた 3・変わらず 409）/ 画像 5 / エラー 0 / セクション: 鍵 1・絞りで外した 4 / 消した 0 / 古い画像 0
```

**落ちた回は、わけがこの記録の末尾に残る。** `pythonw.exe` には画面が無いので、
そこに出ないものはどこにも出ない ── 繋がらない理由も、bit の見立ても、
「前の回がまだ走っています」も、ぜんぶここに来る。

**「変わらず」がページ数とほぼ同じなら、差分の判断が効いている。**
毎回「書いた」が全ページなら、どこかがおかしい（`--force` が残っている、
出力先が回ごとに違う、など）。

## ambər に読ませる

⚙「保存ディレクトリの追加・変更・削除」で出力先を足す。同期の設定は要らない
（ただのフォルダなので）。前書きの `title` が題になり、フォルダがそのまま索引に
なる。

## ハマりどころ

**`AttributeError: OneNote.Application.GetHierarchy` が出たら、それは繋がって
いる。** OneNote の型ライブラリの登録には**中身のない `1.0` の枝**が混ざって
いて、pywin32 がそれを掴むとメソッドの名前が引けなくなる（[pywin32 issue
1488](https://github.com/mhammond/pywin32/issues/1488)）。レジストリの枝を消せば
直るが、**会社の端末はグループポリシーが書き戻す**ので、スクリプト側で避けて
いる ── 版（1.1）を名指しして `EnsureModule` すれば偽の枝を跨げる。どの束ね方で
繋がったかは `-v` で出る。

**`PermissionError: ...\gen_py\....py.100000.temp` は書き込み先の話。**
pywin32 は makepy の作り置きを `site-packages\win32com\gen_py` に置く。Python が
`C:\Program Files\` に入っていると、そこは管理者でないと書けない。**管理者の窓で
一度作る手は使えない** ── その窓は今度は OneNote に繋げない（権限がずれる）。
スクリプトは書けるかどうかを**実際に一つ置いて**確かめ、書けなければ
`%TEMP%\amber-gen_py-3.x` へ逃がす（`os.access` は Windows のフォルダについて
嘘をつくので当てにしない）。逃がしたかどうかは `-v` で出る。

**`No module named 'win32com.gen_py.0EA692EE-...x0x1x1'` は、書く先と読む先の
ずれ。** pywin32 は `import win32com` した時点で `win32com.gen_py` を作り、その
`__path__` を**そのときの**作り置き先で焼き付ける。だから書く先だけ移すと、
makepy は新しい場所へ書き、読み込みは古い場所を探す ── **書けたのに読めない。**
スクリプトは両方を揃えて移す。あわせて `importlib.invalidate_caches()` も呼ぶ
（pywin32 は呼ばないので、作ったばかりのフォルダが「空」に見えることがある）。

**まず `--check`。繋がるかを数行で言う。**

```bat
py -3 scripts\onenote2md.py --check
```

```
Python 3.9 / 64 bit
Office x64
型ライブラリの枝: win32
COM サーバー: ある  C:\Program Files\...\Office16\ONENOTE.EXE\3
ストア版も入っている: Microsoft.Office.OneNote_...

繋がらない。次の一手:
  型ライブラリに win64 の枝が無い（あるのは ['win32']）。
  Office も Python も 64 bit なので、枝を足せば読める。
  この一行（HKCU なので管理者は要らない）:
    reg add "HKCU\Software\Classes\TypeLib\{0EA692EE-...}\1.1\0\Win64" /ve /d "..." /f
```

**足す道は、こちらで埋めて出す。** 繋がらない端末の前に立っている人に
「docs を見て `--probe` の値をそこから写して」と言うのは、注文としておかしい。

繋がったなら一行で終わる ── `繋がった。開いているノートブック 3 冊: 仕事、私用、…`。

`--probe`（29 行）は、`--check` で足りないときに。

**`--probe` に `--out` は要らない。** そして**定時の回が走っている最中でも
断られない** ── 固まっている回を調べるための道具が、その回のせいで
使えないのでは道具にならない（`--list` と `--dry-run` も同じ。書く回だけが
鎖を取る）。

**結果はファイルに落として送ってもらってよい。**

```bat
py -3 scripts\onenote2md.py --probe > "%USERPROFILE%\Desktop\probe.txt" 2>&1
```

（画面の字は UTF-8 で出す。日本語 Windows の既定は cp932 で、**画面に直に
出すぶんには平気でも、ファイルへ向けた瞬間に cp932 になる** ── `✗` が
cp932 に無いので、失敗した行を書こうとしてそこで止まっていた。**いちばん
知りたい行で。**）

**繋がらないときは `--probe`。** この端末で何が起きているかを並べる ── 作り置き先
（書く／読む）、型ライブラリに登録されている版、ProgID から引いた CLSID、makepy が
作った型、`Dispatch` が返したもの。**一行ずつ守ってあるので、途中が転んでも残りは出る。**
そのまま貼ってもらえれば、推し量らずに直せる。

```bat
py -3 scripts\onenote2md.py --out X --probe
```

**`ライブラリは登録されていません`（`-2147319779` / `TYPE_E_LIBNOTREGISTERED`）の
本命は、bit の食い違い。** 型ライブラリの登録は bit ごとに枝が分かれている ──
64 bit のプロセスは `Win64`、32 bit のプロセスは `Win32` を見る。**片方しか無いと、
皮は正しくかぶさるのに呼んだ瞬間に落ちる**（いちばん読みにくい形）。`--probe` が
見つけたらそう言う:

```
1.1 / lcid 0 / Win32 = ...\Office16\ONENOTE.EXE\3  → ある
→ **この Python は 64 bit なのに、win64 の登録が無い（あるのは ['win32']）。**
```

**これはコードでは直らない。** 直し方は二つ:

> **`Win64` を足しても直らないことがある。** OneNote の型ライブラリが
> **Win32 のものしか無い**場合、枝を足しても指す先が 64 bit から読めない
> （`TYPE_E_CANTLOADLIBRARY` / `タイプ ライブラリ／DLL の読み込みエラー`）。
> そのときは **32 bit の Python を使う**しかない。out-of-process の COM
> サーバーなので、**32 bit の Python から 64 bit の OneNote は問題なく触れる。**
> 入っている Python を見るには `py -0p`。

1. **Python の bit を Office に合わせる。** Office が 32 bit なら 32 bit の Python を
   使う。どちらかは `--probe` の `Office の bit` に出る
   （`reg query "HKLM\SOFTWARE\Microsoft\Office\ClickToRun\Configuration" /v Platform`）。
2. **足りない枝を足す。** Office が 64 bit なのに `Win64` が無いなら、登録のほうが
   欠けている。**自分のユーザーにだけ**足せば管理者は要らない（`HKCU` は `HKCR` に
   重なって見え、`HKLM` より優先される）:

   ```bat
   reg add "HKCU\Software\Classes\TypeLib\{0EA692EE-BB50-4E3C-AEF0-356D91732725}\1.1\0\Win64" /ve /d "C:\Program Files\Microsoft Office\root\Office16\ONENOTE.EXE\3" /f
   ```

   道は `--probe` が出した `Win32` の値をそのまま使う。**戻すときは**
   `reg delete "HKCU\Software\Classes\TypeLib\{0EA692EE-BB50-4E3C-AEF0-356D91732725}" /f`。
   会社の端末なので、**やる前に自分の運用ルールを確かめること** ── レジストリを
   触る話で、こちらから勝手にはやらない。

**（版そのものの取り違えもある。）** 会社の端末には型ライブラリが `1.0` と `1.1` の**両方**登録されて
いた。並んでいるだけではどちらが使えるか分からず、片方は実体を指していない ──
その皮で包むと、`GetHierarchy` は見えるのに**呼ぶとここで落ちる。**
スクリプトは 1.1 → 1.0 の順に試し、**実際に呼んで答えが返ったほうを採る**。
`--probe` は版ごとに実体の道と、そのファイルがあるかまで出す。

**`サーバーの実行に失敗しました`（`-2146959355` / `0x80080005`）は権限のずれ。**
昇格した窓から、昇格していない OneNote には COM で繋げない。**普通の窓で叩く。**
タスク スケジューラでも「最上位の特権で実行する」は**外す**。あわせて、OneNote を
先に手で起動しておく。

**`--prune` は `.md` だけ消す。画像は残る。** 消したページが使っていた画像は
`attachments/` に残り、ambər の ⚙「使われていない画像」に並ぶ ── ノートに
付いている画像を機械が消さないのは ambər 全体の決めごとで、ここもそれに従う。
（記録の「古い画像」は別のもので、**書き直したページの古い画像**を数えている。）

**`--prune` は「歩いた場所」しか消さない。** これは一度直した。前の版は出力先
ぜんたいを見ていたので、`--notebook` で一つに絞って走らせると**絞られなかった
ほうのノートブックが一枚残らず消えた**（今回出てこないので、全部「消えた
ページ」に見える）。いまは、その回に歩いたノートブックの下だけを見る。同じ
理由で、**鍵のかかったセクションの下**と**取得に失敗したページ**も残す ──
見えなかった場所は、消えた場所ではない。

**絞って外したセクションは、`--prune` で消えない。** これも一度直した。絞ると
外したセクションは今回一枚も出てこないので、素直に組むと**前回の写しがまるごと
消える**（そして次の回も絞りは同じなので、二度と戻らない）。守っているのは道では
なく**ページ ID** なので、あとから `--flatten-groups` を付けて出力の形が変わっても、
セクションの名前が変わっても効く。鍵のかかったセクションだけは中が見えず ID が
出てこないので、そこは道で守る。

**`--prune` は ambər で直したものも消す。** `onenote_id` を前書きに持つ
`.md`、つまりこのスクリプトが書いたものだけが対象なので、ambər で新しく作った
ノートは触らない。だが**写したページを ambər で直したもの**は、OneNote 側で
そのページを消せば一緒に消える。それが困るなら `--prune` を外す（代わりに、
OneNote で消したページの写しが残り続ける）。

**同期は頼むだけで、待たない。** `--sync` は OneNote に「いま同期しろ」と
言うが、終わるのを待たない（`--sync-wait` の秒だけ待ってから読み直す。既定 15 秒）。
間に合わなければ**次の回で拾う** ── 一時間ごとなので、遅れても一時間。

**ページの名前を変えると、写しは増える。** OneNote 側で題を変えると新しい名前の
`.md` ができ、古い名前のものは `--prune` なしでは残る。`--prune` があれば
消える。

**同じ名前のページが同じセクションに二つあると `名前 (2).md` になる。**
どちらがどちらかは前書きの `onenote_id` で分かる。

**SharePoint / WebDAV へ直に書くと遅い。** 一ファイルごとに PUT と PROPFIND が
走る。ローカルへ出して `robocopy /MIR` で送るほうが速い。

## mac では

**mac の OneNote には、これに当たる口が無い**（COM も、まともな AppleScript の
辞書も）。同じことを mac でやるなら Microsoft Graph の OneNote API を叩くことに
